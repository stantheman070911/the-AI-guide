# 附錄 F：PR 審查提示詞

一份只做審查、不做修改的提示詞，用來對照它所修改的程式碼庫檢查一個 pull request。代理先了解儲存庫，再在這個脈絡下判斷這次修改。

## 使用方式

1. 在程式代理中開啟儲存庫，切換到該 pull request 的分支，或讓代理能取得它的 diff。
2. 把下方區塊貼上作為任務。如果代理看不出你指的是哪一個 pull request，請在開頭註明。
3. 採取行動前，先對照 diff 檢查每一項發現。發現是待驗證的主張，不是已確認的修正。
4. 最後一行讓代理在本次工作階段的後續工作中沿用它對程式碼庫的理解，後續修正可以直接從這裡開始。若要稽核整個程式碼庫而非單一修改，請使用[附錄 E](05-codebase-audit-prompt.md)。

## 提示詞

```markdown
# 審查 PR

徹底探索儲存庫，了解它的架構、核心模組、資料流、相依套件、程式碼慣例與實作模式。

接著在既有程式碼庫的脈絡下審查這個 PR，聚焦於：

* 正確性：邏輯錯誤、邊界情況與非預期的行為。
* 架構：是否與既有的模式和設計決策一致。
* 程式碼品質：可讀性、可維護性、重複與不必要的複雜度。
* 可靠性：可能的回歸、安全性問題、效能疑慮與缺少的測試。
* 整合：與既有元件、介面和資料流的相容性。

依嚴重程度排列可採取行動的發現。每個問題都要指出受影響的檔案與行號、說明影響，並建議具體的修正方式。避免推測性的疑慮與不必要的重構。

不要修改任何程式碼。

最後簡要總結這個 PR、嚴重的發現、測試缺口，以及合併前應處理的風險。

在本次工作階段中，以你對程式碼庫的理解作為後續開發工作的基礎。
```
