# 附錄 G：熟悉程式碼庫提示詞

一份在新增功能的工作階段開始時使用的提示詞。代理先研究程式碼庫並回報所見，之後才動手寫程式。

## 使用方式

1. 在打算新增功能的工作階段開始時，於程式代理中開啟專案。
2. 把下方區塊貼上作為第一個任務。如果你的工具有唯讀模式或規劃模式，請使用它。
3. 閱讀概覽。在提出第一個功能之前，先更正代理理解錯的地方；這裡的錯誤會帶進之後的每一次修改。
4. 接著描述第一個功能。若要審查單一修改，請使用[附錄 F](06-pr-review-prompt.md)；若要稽核整個程式碼庫，請使用[附錄 E](05-codebase-audit-prompt.md)。

## 提示詞

```markdown
請徹底探索並分析這個程式碼庫，全面了解它的架構、結構與實作模式。

在本次工作階段中，我們會陸續新增功能，因此請花時間了解既有功能、關鍵元件、資料流、相依套件與設計決策。

特別留意專案的程式碼慣例、架構模式，以及系統各部分如何互動。

先不要修改任何程式碼。你的目標是對程式碼庫建立紮實的理解，讓之後的功能能乾淨、一致地實作，且不引入不必要的複雜度或回歸。

分析完成後，請簡要概述架構、重要模組、既有模式，以及我們應留意的任何技術限制或潛在風險。

在本次工作階段中，以這份理解作為所有後續開發工作的基礎。
```
